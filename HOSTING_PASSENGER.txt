Passenger production checklist (Valitsa Travel)
==============================================

1) Hosting panel (required if ERR_REQUIRE_ESM or generic Passenger error)
   - Application root: the directory that contains THIS repo's package.json and passenger_entry.cjs (not server/ alone).
   - Startup file: passenger_entry.cjs
   - Save, then restart the Node/Passenger app (or touch tmp/restart.txt if your host documents that).

2) After restart — get the real error
   - Open the site error page and click "Technical details for the administrator of this website."
   - Also read application stdout/stderr in the hosting panel.
   - If logs still show require() of server/index.js, the startup file in the panel is still wrong.

3) On the server (SSH or file manager)
   - Confirm passenger_entry.cjs exists next to package.json in the deployed path.
   - Confirm git revision matches what you expect: git rev-parse --short HEAD

4) Local verification before deploy
   - npm run verify:deploy

5) Document root vs Vite build (two valid layouts)
   A) DocumentRoot = application root (same folder as package.json)
      - Use the repo root .htaccess (committed in the project). It rewrites /admin, /trips, /assets/* into dist/.
      - Run `npm run build` so dist/index.html and dist/assets/ exist next to package.json.
   B) DocumentRoot = only the contents of dist/ (flat static deploy)
      - Use the .htaccess inside dist/ (copied from public/.htaccess at build time).
      - Include hidden files when uploading: .htaccess must not be skipped.

6) Client routes (/trips, /admin/login, …)
   - Without dist/, Express cannot serve the SPA; deep links will 404.
   - If Apache answers before Passenger, root .htaccess (layout A) must be deployed so paths rewrite to dist/index.html.

7) Node.js for builds on the server
   - Vite 8 requires Node.js 20.19+ or 22.12+. Upgrade the host Node selector (e.g. nodevenv) or build locally / in CI and upload dist/.

8) After changing public/.htaccess, run `npm run build` and redeploy dist/ so the built copy in dist/.htaccess matches (layout B).

9) If Apache returns 500 after deploying .htaccess, the host may disallow `Options` in .htaccess — remove the `Options -MultiViews` block from .htaccess and redeploy.
